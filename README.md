# 🥦 リョクシャカ LIVE NOTE

緑黄色社会（リョクシャカ）のライブ・セットリスト・楽曲の披露回数／レアリティと、自分の参戦記録をまとめる Web アプリです。
スマホでの利用を前提にした画面構成で、ホーム画面に追加すればアプリのように使えます。

**公開 URL:** https://kanato-m.github.io/ryokushaka-app/ （GitHub Pages を有効にした後）

## ✨ 主な機能

| 画面 | できること |
| --- | --- |
| 🏠 ホーム | 次のライブ（参戦予定）までのカウントダウン、参戦数・楽曲コンプリート率、年別参戦回数、よく聴いた曲 Top5、回収済み楽曲のレアリティ構成 |
| 🎸 ライブ | 開催予定／過去公演の一覧。キーワード・年・種類（ワンマン／FC／フェス・イベント／TV）で絞り込み。公演ページでセットリスト（レア度付き）、レアリティ構成、同じツアーの他公演を表示 |
| 💿 楽曲 | 公式曲の披露回数・披露率・レア度の一覧（並び替え・レア度／回収状況で絞り込み）。曲ページで年ごとの披露回数と、演奏されたライブの逆引き |
| 🎫 マイ参戦 | 参戦したライブ（参戦予定も可）を検索して追加。現地で聴いた曲の自動リスト、まだ聴いていない曲（聴ける可能性が高い順） |
| 🎰 ガチャ | 過去の披露曲とレア度をもとにセットリストをランダム生成。「リアル（披露率どおり）」「レア狙い」「ランダム」の 3 モード、曲数指定、未回収曲優先に対応。曲順は各曲が過去に何曲目あたりで演奏されることが多いかをもとに並べ、結果のコピー・共有や AI による講評もできます |
| 🤖 AI | Claude（既定）・Gemini・OpenAI 互換 API から選べる AI がセトリ予想や質問に回答。アプリの集計データ（直近のセトリ、各曲の披露率など）を AI に渡して回答させます |

### 💎 楽曲レアリティ判定（旧アプリと同じロジック）

単純な披露回数ではなく「ツアーの規模（同じライブ名の公演数）」で重み付けした披露率で判定します。

* **UR**: 最終披露日から4年以上経過 / **SSR**: 2年以上経過
* **SR**: 直近2年の披露率が4%以下 / **RR**: 8%以下 / **R**: 30%以下 / **UC**: 50%以下
* **C**: 上記以外（定番曲）
* **未披露**: 公式曲だがライブでの披露記録なし ／ **未収録**: 公式曲リストにないカバー曲など（UR扱い）

## 🔄 Streamlit 版からの主な変更点

* **データが自動で最新に**: GitHub Actions が毎日 2 回（3:17 / 15:17 JST）LiveFans から取得し、リポジトリに保存してからアプリを再デプロイします。
  旧アプリでは「取得ボタンを押しても Streamlit Cloud の再起動で消える」「キャッシュで反映されない」問題がありましたが、解消しています。
* **取得処理の不具合修正**
  * 既知の公演に当たった時点で取得を打ち切っていたため、取りこぼしが発生していた
  * 開催予定だった公演が終わった後のセトリ（後日 LiveFans に登録される）を自動で再チェック
  * 開催予定の日付・会場変更や中止を反映
* **データのクリーニング**
  * TV 音楽番組（紅白・Mステ・CDTV など）のセトリに入っていた**他の出演者の曲**を除外（旧アプリでは「現地で聴いた曲」や「未収録」に混ざっていた）
  * 「ShoutBaby」「Tap Tap Dance」などの表記ゆれを統一（`data/song_aliases.csv` で追加可能）
  * MC・SE などの曲ではない行を除外
  * 一度も披露されていない曲が「C（定番）」になっていた問題を「未披露」に修正
* **高速・軽量**: 静的サイトになったので起動待ち（スリープ解除）がなく、すぐ開けます。
* **参戦記録**: 端末内に保存。Google スプレッドシート同期（Apps Script 経由）を設定すると複数端末で共有できます。旧アプリのスプレッドシートの内容もそのまま読み込めます。
* **合言葉画面は廃止**しました（公開データのみを扱い、参戦記録の書き込みは Apps Script の合言葉で保護しています）。

## 🚀 公開までの手順（初回のみ）

1. このブランチを `main` にマージする
2. GitHub のリポジトリ画面で **Settings → Pages → Build and deployment → Source** を **「GitHub Actions」** に変更
3. **Actions** タブ → 「データ更新 & デプロイ」→ **Run workflow** を実行（以後は毎日自動で実行されます）
4. 数分後に https://kanato-m.github.io/ryokushaka-app/ で開けるようになります
5. （任意）スマホのブラウザで開き「ホーム画面に追加」

旧 Streamlit Community Cloud のアプリは不要になるので、削除して構いません。

### ☁️ Google スプレッドシート同期の設定（任意）

1. 参戦記録用のスプレッドシート（旧アプリで使っていたものでも OK）を開き、「拡張機能 → Apps Script」
2. [`gas/Code.gs`](gas/Code.gs) の内容を貼り付け、`TOKEN` を好きな合言葉に変更して保存
3. 「デプロイ → 新しいデプロイ → 種類: ウェブアプリ」、実行ユーザー「自分」、アクセスできるユーザー「全員」でデプロイ
4. 表示された URL と合言葉を、アプリの **設定（⚙️）→ Google スプレッドシート同期** に入力して「保存して同期」

※ スプレッドシートは「表示名」「ライブ情報（LiveFans の URL）」の 2 列で保存されます。

### 🤖 AI アシスタントの設定（任意）

アプリの **設定（⚙️）→ AI アシスタント** で、使う AI と API キーを入力します。キーはその端末のブラウザ内にのみ保存され、選んだ AI の会社にだけ送信されます（利用料金は各社のアカウントに請求されます）。

| 使う AI | API キーの取得先 | 既定のモデル |
| --- | --- | --- |
| Claude（Anthropic） | [Claude Console](https://platform.claude.com/settings/keys) | `claude-opus-5-5`（`claude-sonnet-5-5` / `claude-haiku-5-5` に変更すると安くなります） |
| Gemini（Google） | [Google AI Studio](https://aistudio.google.com/apikey)（無料枠あり） | `gemini-flash-latest` |
| その他（OpenAI 互換） | 各サービス | ベース URL とモデル名を入力（OpenAI・OpenRouter・Groq など） |

## 👥 ほかの人への共有

公開 URL（https://kanato-m.github.io/ryokushaka-app/ ）を送るだけで、誰でもログインなしで使えます。

* **共通**: ライブ一覧・セットリスト・楽曲の披露回数／レアリティ（毎日自動更新）
* **人ごとに別々**: 参戦記録・AI の API キー・スプレッドシート同期の設定は、それぞれのブラウザ内に保存されます。
  共有された人は空の参戦記録から始まり、あなたの記録やスプレッドシートが見られたり書き換えられたりすることはありません。
* 共有された人がスプレッドシート同期を使いたい場合は、その人自身のスプレッドシートで「Google スプレッドシート同期の設定」を行います。

## 🗂️ ファイル構成

```
data/
  LiveList.csv       ライブ一覧（自動更新）
  Setlists.csv       セットリスト（自動更新）
  SongList.csv       公式リリース曲の一覧（★新曲が出たら手で追記）
  song_aliases.csv   曲名の表記ゆれ → 正式名の対応表
  mylive.csv         旧アプリの参戦記録のバックアップ（設定画面の「CSV を読み込む」で取り込み可）
scripts/
  update_data.py     LiveFans から取得して data/*.csv を更新
  build_data.py      data/*.csv から web/data.json を生成（クリーニング込み）
web/                 アプリ本体（HTML / CSS / JavaScript、ライブラリ不要）
gas/Code.gs          スプレッドシート同期用 Apps Script
.github/workflows/   自動更新・デプロイ・テスト
tests/               スクリプトのテスト
```

### 新曲が出たとき

`data/SongList.csv` に `曲名,リリース日,初収録アルバム名` の形で 1 行追加して `main` に push すると、自動で再デプロイされます。
（アプリの「楽曲」画面下部の「公式曲リスト外でセトリに登場した曲」に新曲が出ていたら追加のサイン）

## 🛠️ ローカルでの動かし方（自分用メモ）

```bash
pip install -r requirements.txt
python scripts/update_data.py      # LiveFans から最新データを取得（任意）
python scripts/build_data.py       # web/data.json を生成
python -m http.server 8000 -d web  # http://localhost:8000 で開く
```

テスト: `python -m unittest discover -s tests -v`

## ⚠️ 注意

* データの取得元は [LiveFans](https://www.livefans.jp/) です。サイトの構造が変わると取得に失敗することがあり、その場合は Actions の実行結果が赤くなります（アプリは既存データのまま動き続けます）。
* GitHub の仕様で、リポジトリに 60 日間まったく動きがないと定期実行が自動停止することがあります。その場合は Actions タブから再度有効にしてください。
